# Contracts — Sharded-Docstore (Team 50)

> **Status: FROZEN** — Agreed and signed off by all members.
> Any change requires a PR approved by all three members.
> This document is the single source of truth for every interface decision.

---

## 1. Document IDs and Ranges

- `doc_id` is a **non-negative 64-bit integer**, valid range `0 … 2^63 − 1`.
- Reject strings, floats, negatives, and booleans at the API boundary.
  Python treats `True` as `int(1)` — validate `isinstance(v, bool)` first and reject it.
- `doc_id` is **unique** and **immutable** after insertion.
- Shard ranges are **half-open `[start, end)`**; together they cover `[0, 2^63)` with
  no gaps or overlaps.
- A document stays on its shard unless an explicit migration moves its range.
- **Note:** IDs above `2^53` can lose precision in some JSON clients; our Python client is fine.

---

## 2. Update and Delete Semantics

- `PUT /doc/{id}` is a **full replacement**. The body must contain the same `doc_id`.
  Missing document → `NotFound`. `doc_id` cannot change.
- `DELETE /doc/{id}` on a missing document → `NotFound`.
  A **retried** delete with the same `request_id` returns the original success (idempotency).
- *(Stretch, only if time remains)* `$set` / `$unset` partial updates.

---

## 3. Sequence Numbers, Terms, Epochs

- Each **shard** keeps one monotonically increasing, gap-free sequence starting at **1**,
  **not reset** by failover or epoch changes.
- **Committed** sequence positions are permanent. An **uncommitted** tail that exists only
  on a failed primary may be discarded; its `seq` values are reassigned by the new primary
  under a higher `term`.
- An operation is identified by the pair **(term, seq)**; within one term a `seq` maps to
  exactly one operation (log-matching rule).
- The follower accepts only `last_seq + 1`; a gap triggers a catch-up request;
  a duplicate is handled idempotently.
- **Two separate fencing values:**
  - `ownership_epoch` — per **range**; bumped on failover (every range of the affected shard)
    and on migration (the migrated range only).
  - `term` — per **shard**; bumped on every primary change; carried in every WAL record
    and replication message.
- Nodes persist their current `term` and per-range epochs durably (fsync) so a restart
  cannot forget them.
- Writes carrying a stale `ownership_epoch` or `term` are **rejected**.

---

## 4. Idempotency

- Every client write carries a unique `request_id` (UUID4, generated by the client library);
  retries **reuse** the same `request_id`.
- `request_id` is stored in the WAL/oplog and preserved by the follower.
- A repeated `request_id` returns the **original result** and never executes twice.
  The lookup must also cover in-flight/pending operations.
- **Dedup table:**
  - Survives restarts: rebuilt from WAL **and included in snapshots**.
  - Bounded window: last **10 minutes** or **100 000 entries** (whichever is hit first).
  - Eviction policy: **FIFO** (insertion order via `collections.OrderedDict`).
  - Retries older than the window are unsupported — documented limitation.
  - Included in snapshot resync to a follower; survives failover.

---

## 5. Query Semantics

- A **missing field** never matches any operator.
- `null` matches only an explicit `null` value (not a missing field).
- `$gt` / `$lt` compare only same-type scalars (number ↔ number, string ↔ string).
  Booleans are **not** numbers. Mismatched types → no match.
- **Total sort order:** type rank (missing < null < boolean < number < string), then value;
  arrays/objects are not sortable.
- `doc_id` is the **deterministic tie-breaker** for every sort.
- Global `skip` / `limit` are applied by the **router after merging** (Module 5.3).

## 6. Read and Write Policy

### Write outcomes (exactly three)

| Outcome | Meaning | HTTP |
|---|---|---|
| `COMMITTED` | Follower has durably fsynced the record; committed. | 200 |
| `REJECTED` | Definitely not applied; safe to retry with the same `request_id`. | 4xx/503 |
| `outcome_unknown` | WAL-appended on primary, but no durable follower ack in time. | 202 |

**Reject reasons** (all return `REJECTED` before any WAL append):
validation failure, stale epoch/term, lease expired or too little lease remaining,
duplicate key, range paused, not primary, `REPLICATION_UNAVAILABLE` (no `SYNCED` follower).

**Commit point:** an operation is committed when the **follower has durably fsynced its WAL record**.
A lost follower ack or a primary crash before the client reply does not change this.
Records present **only** in the primary's WAL are uncommitted.

### Read policy

- **Primary reads:** served only by the current primary **holding a valid lease**; reflect
  all acknowledged writes.
- **Follower reads:** may be stale; response must include `applied_seq` and `replication_lag`.

### Replica states

`SYNCED` → `CATCHING_UP` → `DOWN`

- Writes accepted only while follower is `SYNCED`.
- Follower not `SYNCED` when write arrives → `REPLICATION_UNAVAILABLE` (nothing appended).
- Follower fails **after** primary WAL append → wait up to T=1 s, then `outcome_unknown`.
- While a pending (uncommitted) operation exists, further writes on that shard are blocked
  until it is reconciled.

### Degraded mode

After a failover the promoted primary serves reads immediately but **rejects writes**
(`REPLICATION_UNAVAILABLE`) until the old primary rejoins and becomes `SYNCED`.
Synchronous replication is **never** relaxed (no single-node acknowledgements).

## 7. Leases and Timing

| Parameter | Symbol | Default |
|---|---|---|
| Heartbeat interval | H | 1.0 s |
| Lease duration | L | 3.0 s |
| Failure-detection timeout | D | 5.0 s |
| Safety margin | M | 0.5 s |
| Replication timeout | T | 1.0 s |

**Startup validation rules** (enforced in `config.py`):
- `H < L < D`
- `T + M < L − H` (i.e. `1.5 < 2.0` ✓ with defaults)

**Lease rules:**
- Primary computes expiry from the time it **sent** the heartbeat (conservative).
- Coordinator computes expiry from the time it **granted** the lease.
- Before starting a write, primary needs **remaining lease > T + M**; otherwise wait briefly
  for renewal or reject.
- If lease expires before the client acknowledgement → `outcome_unknown`.
  Never return `COMMITTED` after lease expiry.
- Coordinator waits for the old lease to expire **plus M** before the new primary may write.
- A restarted node must register and obtain a fresh lease; it never resumes as primary
  from its old state.
- Clock assumption: **monotonic clocks for elapsed time only**; single-host Docker Compose;
  no cross-machine clock comparison.

## 9. Interfaces

### Error model

All errors return JSON: `{"error_code": "<CODE>", "error_message": "<human text>"}`.
**No stack traces in error responses.** Details go to structured logs only.

| Code | HTTP | Meaning |
|---|---|---|
| `STALE_EPOCH` | 409 | `ownership_epoch` is behind the current epoch |
| `STALE_TERM` | 409 | `term` is behind the current term |
| `NOT_PRIMARY` | 409 | Request sent to a non-primary node |
| `LEASE_EXPIRED` | 409 | Primary lease has expired |
| `RANGE_PAUSED` | 503 | Range paused for migration |
| `INVALID_QUERY` | 400 | Query filter violates grammar or size limits |
| `DUPLICATE_KEY` | 409 | Insert with an existing `doc_id` |
| `NOT_FOUND` | 404 | Document not found |
| `OUT_OF_RANGE` | 400 | `doc_id` outside this shard's owned ranges |
| `OUTCOME_UNKNOWN` | 202 | Write appended to primary WAL but no follower ack |
| `REPLICATION_UNAVAILABLE` | 503 | No `SYNCED` follower; write rejected before WAL append |
| `AUTH_FAILED` | 401 | Invalid cluster secret, admin token, or client API key |
| `BODY_TOO_LARGE` | 413 | Request body or document exceeds size limit |
| `VALIDATION_ERROR` | 422 | Pydantic input validation failure |

### Authentication

- **Cluster secret** (`CLUSTER_SECRET`): HMAC-SHA256 over the raw request body,
  sent in the `X-Cluster-Signature` header; used for all inter-node RPC.
  Verified with `hmac.compare_digest`.
- **Admin token** (`ADMIN_TOKEN`): sent in `X-Admin-Token` header; used for coordinator
  admin endpoints only. Separate from the cluster secret.
- **Client API key** (`CLIENT_API_KEY`): sent in `X-Api-Key` header; used by the router.

### Response metadata

Every response includes:
```json
{
  "served_by": "<node_id>",
  "term": 1,
  "ownership_epoch": 3,
  "applied_seq": 42,
  "replication_lag": null
}
```
`replication_lag` is `null` for primary reads, non-null (ops behind) for follower reads.

**Shard node — public:**
`POST /doc`, `PUT /doc/{id}`, `DELETE /doc/{id}`, `GET /doc/{id}`,
`POST /query`, `GET /health`, `GET /status`

**Shard node — internal (`/internal/*`):**
`POST /internal/replicate`, `POST /internal/catchup`, `GET /internal/snapshot`,
`POST /internal/snapshot/apply`, `POST /internal/fence`

**Coordinator:**
`GET /shardmap`, `POST /register`, `POST /heartbeat`,
`POST /admin/migrate`, `GET /admin/status` *(admin token required)*

**Router:**
`POST /doc`, `PUT /doc/{id}`, `DELETE /doc/{id}`, `GET /doc/{id}`, `POST /query`
*(client API key required)*
